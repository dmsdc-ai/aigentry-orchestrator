# #1165 로컬 지식 검색 방법론 비교 — 설계 제안
결속: task1165 | sid rag1165-researcher | attempt 8cebcd59-633d-4662-bc39-c26c05114a5b | operation rag1165-v1.
**권고: exact/어휘 검색을 필수 기반으로 하는 하이브리드 RAG를 목표로 삼고, 결정·정정·시간을 표현하는 작은 스키마를 곁들인다. Dense는 검증 후 선택 활성화하고, 로컬 그래프는 관계 질의의 실측 이득이 있을 때만 추가한다. 전체 커뮤니티 GraphRAG는 현재 보류한다.**
온톨로지는 개체·관계·의미 제약을 정하는 표현 체계이고, RAG는 근거를 찾아 생성에 사용하는 흐름이다. 서로 대체재가 아니며 작은 스키마만으로 완전한 온톨로지·추론 엔진을 도입했다고 부르지 않는다. 아래 선택·비용 판단은 E1–E5를 적용한 설계 추론이다.

| 방법 | 해결하기 좋은 질문 | 비용·실패 지점 | 본 과제 적합성 |
| --- | --- | --- | --- |
| 순수 vector RAG | 표현이 다른 의미 질문 | embedding 생성·갱신, ID/부정어/한영 코드 구별 실패 가능; 관계·시간 보장 없음 | 단독 기본값보다 비교군으로 적합(E1/E2/E5) |
| 어휘+dense 하이브리드 RAG | 정확한 용어와 의미 유사성이 섞인 질문 | 두 색인·순위 융합·한국어 분절 평가; 생성은 인용 검증 별도 | 권장 목표; exact/어휘만으로도 발췌 제공(E2/E5) |
| 온톨로지 안내 검색 | 결정 종류·정정·유효 시점으로 후보 제한 | 스키마 설계·별칭/동명이인 해소·변경 이력 유지; 잘못된 타입은 누락 유발 | 작은 선택 필드부터; 미분류 근거를 폐기하지 않음(설계 추론) |
| 로컬 그래프 탐색 | 특정 결정의 선행 근거·변경 관계를 잇는 질문 | 관계 추출 오류·경로 검증·증분 무효화; 연결 자체는 인과 증거 아님 | 검증된 명시 관계만 제한 탐색; graphDB 필수 아님(E3/E4에서 착안) |
| 전체/커뮤니티 GraphRAG | 허용 자료 전체의 반복 주제·큰 흐름 | 개체 추출·군집·계층 요약·map-reduce, 광범위 갱신·권한별 요약 비용 | 반복되는 전역 질문과 평가 이득이 확인될 때 재검토(E3/E4) |
Microsoft Local Search는 추출 그래프와 원문 조각을 함께 쓰는 라이브러리 모드다. 여기서 제안하는 명시 관계의 제한 탐색과 동일 구현이라고 주장하지 않는다(E4).

질문 라우팅은 인증된 프로젝트/선택 자료/시간 범위를 먼저 고정하며, 아래 순서로 결정한다. 그래프·전역 모드는 승격 게이트 통과 전 비활성이다.

| 우선순위·형태 | 합성 예시 | 결정 규칙·보수적 fallback |
| --- | --- | --- |
| 1. 명시적 전체 범위+주제 요청 | “이 프로젝트 전체에서 반복된 보류 이유는?” | 승인 범위의 최신 커뮤니티만 사용; 비활성·초과 예산이면 범위 축소 안내와 부분 근거, 전체를 봤다고 하지 않음 |
| 2. 결정/관계/시간 요청 | “결정 D17은 어떤 근거로 바뀌었고 8월에는 무엇이 유효했나?” | exact seed→결정/정정·유효시점 필터→필요한 명시 관계 최대 2홉; 그래프가 낡으면 원문/이력 검색으로 강등 |
| 3. ID/이름 조회 | “TS-999 기록”, “KnowledgeService 정의” | exact ID/심볼·확인된 별칭 우선; 동명이인 복수면 후보 범위만 명확화; 실패 시 같은 범위 어휘 검색 |
| 4. 나머지 의미 질문 | “인터넷 없이 쓰려던 이유가 뭐였지?” | 어휘+dense 병렬→중복 제거·순위 융합; dense 부재/버전 불일치면 어휘만 사용 |
복합 질문은 위 우선순위를 따르되 ID는 seed/필터로 보존한다. 의도 불명은 제한 어휘 검색 또는 한 번의 명확화이며 자동 전역 탐색·범위 확대를 하지 않는다. “왜”의 답은 원문에 적힌 이유만 인용한다.

축적은 동의된 intake→stored→추출 성공 시 queryable로 구분하고 reviewed는 별도 인간 검토 상태다. 기계 추출·요약·관계는 evidence-only이며 저장 또는 높은 검색 점수가 인간 승인으로 승격시키지 않는다. 일상 저장/질문에 새 검토 대기열을 만들지 않고 개인 화면·소리 자동 수집도 하지 않는다.
원문 보존 chunk를 문단·발화·코드 경계로 나누고 occurrence/revision/hash/원본 byte anchor를 유지한다. 제목·발화자·날짜 등 원문 문맥을 우선 붙이며, STT 시간 anchor는 검증된 원본 매핑이 있을 때만 제공한다. 정규화·LLM 생성 문맥은 원문과 분리하고 생성기 버전·모든 의존 원문을 남긴다(E5의 문맥 손실 문제에 대한 적용).
온톨로지는 초기에는 결정/제안/근거/정정, 명시적인 대체 관계와 기록시점/유효시점만 둔다. 한국어 조사·띄어쓰기, 영문 별칭, 코드 대소문자·기호, 동명이인·부정어는 별도 평가한다. 자유 서술은 유지하고 필수 수작업 태깅을 요구하지 않는다.
증분 갱신은 검증된 연속 commit에 결속하고 chunker/tokenizer/embedding/schema/extractor 버전을 기록한다. 변경된 원문→chunk→edge→summary→answer/cache 의존성을 무효화한다. 군집 변화는 다른 커뮤니티에도 영향을 줄 수 있어 GraphRAG 갱신을 항상 국소·저비용이라고 가정하지 않는다.
파생 그래프/색인은 기존 coreRoot **밖**에 둔다. 기준안이 보고한 strict allowlist와 읽기 전량 검증 비용은 그대로 남으며 새 색인이 지연을 해결했다는 주장은 금지한다. 원본·권위·버전 manifest를 보존해 서버에서 재색인할 수 있게 하되 이관 구현/검증은 별도다.
현재 ACL·동의·철회·정정은 검색/scoring 전, 모든 외부 전송 전, 텍스트/미리보기/내보내기/음성/재생 출력 전 확인한다. 엣지와 집계·요약·캐시도 전체 기여 원문의 provenance와 현재 권위를 증명해야 한다. 권한 혼합 자료로 만든 요약을 나중에 문장 필터링해 재사용하지 않는다.
전역 군집·요약은 현재 허용 corpus에 결속된 것만 사용한다. 숨겨진 자료의 제목·개수·존재를 유추시키는 무필터 요약도 금지하며 의존성/최신 권위를 확인할 수 없으면 내용을 차단한다. 철회 시 진행 중 생성과 대기 출력도 취소한다.
충돌은 양쪽 원문·유효 시점과 함께 드러낸다. token 부족이면 불완전함을 알리고 결론을 보류한다. no-hit은 “현재 선택한 범위에서 근거를 못 찾았어요”, 그래프 stale은 원문 경로, 원본 검증 실패/권위 불명은 내용 없는 오류로 끝낸다. 생성기 부재는 검증된 발췌로 대응한다.
다양한 LLM/STT/TTS/embedding/reranker 어댑터는 선택 기능이며 목적·데이터·목적지가 허용된 egress만 쓴다. 클라우드 구독이 API 권한/요금을 포함한다고 약속하지 않고, 실패 시 다른 provider로 몰래 전송하지 않는다. PC를 현재 권위로 두며 분리된 폰/서버가 최신 철회를 확인 못 하면 private cache도 차단한다.
VoiceCode는 같은 근거 계약으로 짧은 답→출처/상세를 제공한다. cancel/barge-in은 생성·대기 audio를 취소하고 “다시”도 현재 권위를 재검증한다. 연결/오디오 경로 변경 시 멈추며 스피커로 자동 공개하지 않는다. Fold7/Buds2Pro 지원·STT/TTS 성능은 미측정이다.
TaskAdvisor ON/제안 전용, TaskLoop OFF/명시적 긍정 인간 활성화 전 실행 금지를 유지한다. 과거 문서의 승인은 현재 실행 권한이 아니다.

평가·예산은 모두 **제안값, 이번 실행 없음**이다. 원본 계보로 dev/holdout을 분리한 합성 한/영/코드 corpus에서 ≥100개 answerable holdout(네 라우팅군 각 ≥25), 별도 ≥40개 무근거/모호 질문을 만든다. 각 관련 근거·관계 방향/타입·유효 시간·충돌·정확 anchor를 사람이 gold로 확정한다.
같은 corpus·생성기·token 예산으로 exact+어휘, 순수 dense, hybrid, hybrid+원문 문맥, hybrid+생성 문맥, hybrid+작은 스키마, hybrid+스키마+local graph를 비교한다. 전역군에서만 해당 기준군과 community 요약을 비교하고 재랭커는 별도 on/off로 분리한다. 구현·benchmark 실행은 후속 승인 범위다.
초기 탐색 상한은 어휘/dense 각 30 후보→중복 제거 후 최대 60→최종 근거 10개/4,000 input tokens, 출력 400 tokens다. 그래프는 2홉/50 edge, 전역은 최대 8 community report와 동일 입력 총량으로 제한한다. 초과 시 부분 범위를 고지하며 충돌 근거를 조용히 버리지 않는다; dev에서 조정 후 holdout 전 고정한다.
검색 recall@10/nDCG@10은 현재 허용 gold 근거 기준으로 계산한다. 인용의 주장 지지 정밀도·사실절 coverage, 원본 anchor 해상, 관계/path 전체 일치(방향/타입/시점/각 edge 근거), 충돌 보존, 답변 보류와 오보류율은 서로 분리한다. 자동 judge만으로 진실을 확정하지 않는다.
비용은 cold/warm p50/p95 검색·원본 integrity/ACL·생성·전체 지연, ingest/증분·전체 재색인 시간, 메모리/저장, 모델별 token/호출/요금, 스키마·동명이인·edge 정정 분/100자료를 각각 기록한다. 100/1k/10k 자료에서 core 검증 비용까지 포함한다.
승격 공통 게이트: recall@10 ≥90%, 주장 지지 정밀도/인용 coverage 각각 ≥95%, 모든 출력 anchor 정확 해상, gold 충돌 양측 보존 또는 불완전성 명시 100%, ≥50 권한/철회·cache/audio race fixture에서 무권한 노출 0건. 표본 통과는 제품 전체 보안 보장이 아니다.
선택 개선은 paired 95% 구간과 언어/질문군별 결과를 보고하며 recall/nDCG 저하 한계 2 percentage points를 사전 등록한다. 개선 여지가 크면 유의한 이득, 이미 포화라면 동일 품질에서 비용/지연 이득을 요구한다. 논문의 상대 향상률을 보편 승격 조건으로 쓰지 않는다.
로컬 그래프는 opt-in으로 제공된 실제 관계 질문 사례가 반복되고, 관계 holdout에서 path 완전일치 ≥95% 및 hybrid+스키마 대비 개선의 paired 구간 하한 >0일 때 채택한다. 소표본으로 결론 불가하면 보류한다. 추가 유지보수는 초기 예산 ≤30분/100개 신규·정정 자료로 사전 고정하고 사용성 결과로 재결정한다.
기준안 목표인 PC 검증 포함 발췌 p95 ≤1초·첫 검증 생성 text ≤3초·8초 deadline과 첫 음성 ≤15초·중단 p95 ≤250ms를 함께 확인한다. 비용 상한 미설정의 원격 옵션은 승격하지 않는다. 관계 수요가 드물거나 원문/스키마만으로 충분하거나 무효화/지연/유지보수 게이트를 못 넘으면 그래프를 미룬다.
전역 GraphRAG는 반복되는 전체 주제 질문에서 사람이 평가한 근거 있는 주제 coverage가 bounded hybrid 요약보다 개선되고 위 권한·충돌·시간·비용 게이트를 만족할 때만 도입한다. 초기 상한이 전체 범위를 덮지 못하면 그 구성은 전체 요약으로 승격할 수 없다.

공식 1차 자료는 아래 **5개만 2026-09-13 직접 HTTP 200으로 확보**했다. E1/E2는 초록만 읽었으며 PDF·외부 연결 문서는 수집하지 않았다. 직접 인용 없이 요약했고 저자 실험은 본 제품 측정값이 아니다.
