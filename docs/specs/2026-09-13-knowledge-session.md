## 2. Verified completion and durable delivery

**P publisher:** a trusted orchestrator acceptance adapter, outside any LLM worker, validates task/release admission, exact assigned attempt/operation, reviewed artifact closure/hash, required review/validation receipts and authenticated reviewer authority. Only that adapter commits acceptance; REPORT, status=done, screen glyph, clean process exit and transport ACK cannot publish it.
Event envelope: `schemaVersion, eventClass, tenant/project, taskId, attemptId, operationId, artifactId, artifactRevision, artifactSha256, sourceSequence, kind, sourceAuthority, ACLRef/epoch, provenanceRefs, origin, causationId`; `acceptanceId` is required for authoritative completion/change, while audit evidence carries a separate authenticated `auditAdmissionRef` and never an implied acceptance.
Completion logical identity is `(tenant, project, task, attempt, operation, artifact, revision, hash, completion.accepted)`; canonical encoding + digest gives eventId. An accepted multi-artifact manifest hashes the complete closure. Hash alone never merges distinct ACL-scoped occurrences.
Correction/retraction/tombstone uses its own authorized operation/revision/hash and event kind, points to the affected accepted event/revision, and carries a monotonic per-source sequence. Same identity with different payload is rejected/quarantined, never overwritten.
**D:** nominate/integrate that publisher with the owning task acceptance writer; no measured transactional task API exists. Existing queuewriter is not approved integrated authority; this spec neither installs it nor grants it authority.
**P target coupling:** the approved acceptance authority durably commits acceptance plus outbox in one transaction, using the proposed PostgreSQL authority/jobs/outbox boundary when integrated. Immutable verified blob staging precedes commit; referenced bytes must be durable before acceptance is visible. JSON task status is then a projection, not a second authority.
**P legacy bridge:** before legacy status mutation, the trusted adapter fsyncs an immutable accepted receipt plus pending-publication record under one serialized journal commit. Legacy queue writers must use the same serialization boundary or become read-only projections; independent read/modify/rename writers cannot promise no-loss.
Reconcile that journal against destination receipts on startup/wake, reconnect and bounded supervisor ticks; replay every unacknowledged receipt, not only rows still marked done. Retain journal entries until durable destination receipt/checkpoint and retention policy allow compaction; missing/corrupt history blocks intake with an explicit gap.
Pre-migration legacy done rows enter verification backlog; never synthesize acceptance from them. Snapshot/review accepted artifacts before pruning/migration. Uninstrumented live acceptance writers or disappearing artifacts are a release blocker, not a recoverable guarantee inferred from polling.
**P delivery:** dispatcher returns after local durable acceptance/publication commitment, without waiting for KnowledgeService. Retrying sends at least once; KnowledgeService validates publisher and source ACL, inserts unique logical receipt + job transactionally, then ACKs. No physical exactly-once claim.
If destination ACK is lost, resend eventId and receive the same receipt. If local publication cannot persist, show acceptance-pending and retain evidence for recovery; never silently mark ingestion queued. Next unrelated task does not depend on consumer availability.
Notifications only wake consumers; durable rows/journal are truth. Set finite storage/queue quotas, alert/backpressure intake explicitly when full, retain unacknowledged accepted events, and never silently evict them to keep a green status.

## 3. Ingestion, evidence and changes

KnowledgeService is the authenticated entry point; PostgreSQL owns job/ACL/current overlay, EvidenceStore/blob retains immutable originals and provenance, Qdrant/cache are derived. These are inherited proposals requiring implementation, not an already-available endpoint.
Consumer reads only approved task artifacts through scoped logical refs; verify hashes, source principal/ACL, class-specific admission receipt and evidence byte anchors. The authoritative lane requires acceptance; the optional audit lane requires approved evidence admission. Recheck current authority before ingest commit and every retrieval/cache/context delivery; metadata supplied by a worker is not authentication.
Preserve original occurrence/revision/hash, source task/attempt/operation, review provenance, authored timestamp and ingestion receipt. Generated summaries are labeled derived, reference every contributing revision and cannot become human decisions or execution grants.
Correction appends supersession history without destroying originals; conflicts remain explicit. Process per-source sequence, hold missing predecessors, and make tombstone/revocation authoritative even if an older completion arrives later.
Retraction/tombstone transaction updates the current denial barrier plus outbox before index processing; exclude affected data immediately at authoritative read/admission and cancel dependent in-flight responses. Purge derived vectors, lexical entries and caches idempotently; report projection lag/failure until confirmed.
Retain non-serving provenance/tombstone audit under source retention rules. Physical original deletion is not authorized here; if separately approved upstream, propagate its deletion event to all derived stores/backups according to that approved policy. Already delivered content cannot be recalled.
Only allowlisted acceptance/change kinds enter the authoritative lane. A separate optional `eventClass=audit.evidence` admits approved `failure`, `HOLD` and `checkpoint` task artifacts through a trusted audit adapter; scope/ACL approval permits storage as evidence, not acceptance of the worker's statements as facts.
Audit preserves original bytes/provenance, claimed outcome and explicit unverified/evidence-only labels in storage, retrieval and derived summaries. Its logical identity includes eventClass/kind plus exact tenant/project/task/attempt/operation/artifact/revision/hash; authenticated audit admission and outbox/receipt dedup use the same durability and ACL/barrier rules, without publishing accepted completion.
Audit has separate finite event/byte/retention limits within the role budget, never starves authoritative changes, and reports disabled/queued/blocked/failed honestly. Admission is limited to existing authorized task artifacts; no raw-screen scraping, credentials, personal capture or private-cloud transfer. Audit absence or quota failure cannot block task dispatch or become accepted knowledge.
An actual human approval record requires positive authenticated authority, exact subject/task/attempt/operation/artifact revision/hash and granted scope, plus current validity/revocation checks. A copied approval phrase in any report/checkpoint remains quoted evidence; this service only preserves/verifies the authority reference and cannot mint or expand grants or activate work.
`origin=knowledge-derived`, job receipts, consumer REPORTs and health events cannot re-enter either lane as source events; trusted code enforces causation-cycle rejection and idempotent receipts. Noncompletion audit cannot emit accepted completion, create tasks, execute work or recursively ingest itself; later verified acceptance is a separately authorized event linked to the audit, never relabeling the original.
Resident workers cannot create tasks, mark tasks done, activate Loop, approve Advisor proposals or write task/dispatch queues. Reprocessing is an exact scoped operation under the existing release-bound role assignment, not a newly created task per event.

## 4. Desired role, attempts and Cleaner

Persist project-specific desired role `(tenant/project, ownerTaskRef, releaseRef, scopeRevision, enabled, budget)` with installer/controller-validated admission. References identify that installation's authorized standing assignment/release scope, not development #1173/#1165/#1171; users' boards need none of those numbers. Exact source event task/attempt/operation binding remains mandatory.
For a newly provisioned authorized project, resident is requested enabled by default while its orchestrator is active; preserve an existing explicit disable on upgrade. Configuration defaults grant no bootstrap, acceptance-publisher, task-writer or authentication authority. Missing backend, owner/release binding or valid authority yields visibly blocked with desired intent retained; automatically reconcile when available without repeated approval prompts.
Admission expiry blocks claims without changing persistent desired intent or deleting backlog; cross-release renewal requires valid project admission. Only explicit authenticated user disable/revoke changes persistent desired authority, retaining evidence/backlog under its retention rules.
One owner lease per desired role uses server time, CAS acquisition/renewal, monotonically increasing fence and runtime epoch. Attempts are replaceable `(sid, attemptId, workspace, fence)`; every claim, heartbeat, commit and ACK checks current epoch/fence/expiry.
Separate role lease from bounded job leases. Stale owner/attempt cannot commit even after waking or reconnecting; the durable receipt survives consumer death. No stored PID/lease/grant from backup establishes a new owner.
Reuse reconciler/supervisor ensure and existing terminal/cleanup actuators: a small knowledge drain worker is a service role, not a second host scheduler. Timed retries and lease renewals use the existing scheduling/timer boundary; database jobs implement work ownership only.
Default design profile for validation: one active drain per role, at most 20 events/attempt, 5 min wall time, 3 transient attempts/event with 1/5/30s bounded jittered retry delays; then dead-letter with explicit authorized replay. Security/ACL/integrity failures block immediately. Profile must be configurable and bounded.
Idle drain blocks on event notification with bounded non-LLM reconciliation/lease timers. Empty queue makes zero model calls. Deterministic ingestion is baseline; optional summary jobs require existing model entitlement and explicit per-attempt/daily token/spend caps; zero entitlement means zero model calls.
Rotate context at event/byte/token/wall-time limit using durable cursors/receipts, not transcript continuity. A failed/hung attempt loses its fence, is retired through Cleaner, and gets a bounded replacement; no auto-restart can bypass attempt admission or revive a revoked fence.
Normal orchestrator stop/sleep suspends and fences the runtime attempt, cancels pending model work and uses existing stop/cleanup actuators; it never writes desired.enabled=false. Unexpected crash cannot rely on a shutdown hook: runtime lease expiry fences the abandoned attempt, and boot/wake reconciles/reacquires a fresh epoch/fence before work; no claim of instant crash detection.
On boot/wake automatically reconcile both lanes' durable backlog and resume if configured enabled and current project admission valid; missing authority/backend remains visibly blocked. Explicit user disable/revoke alone persists the changed desired authority and fences active work; boot/reconnect cannot override it. Revoked/expired attempts never revive through auto-restart.
Cleaner protection requires trusted desired-role record plus current active lease and matching attempt/workspace; never a name containing knowledge, static keep_alive or an immortal hung process. Unknown authority postpones destructive cleanup with visible blocked state; expired leases permit fenced replacement.
Recheck eligibility immediately before every kill/close/prune, including direct cleanup, scheduler tick, reconciler sweep and auto-cleanup-on-exit. Preserve controller/ancestors, in-flight/HITL work and reviewed artifacts; retain failed cleanup reservations with retry. Confirm both process/telepty and applicable terminal removal for exact attempt identity.
Ingestion failure is isolated from Task Loop/Advisor and next-task dispatch. All share the controller's task-writer ownership boundary; the knowledge role has no queue mutation capability. Transport/service ACL grants are per event, never unlimited repo/network/tool authority for a resident LLM.
