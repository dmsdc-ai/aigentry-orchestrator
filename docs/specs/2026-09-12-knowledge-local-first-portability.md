# #1165 r2 보완 — 로컬 우선·서버 이식성 설계
task=#1165 | sid=kr1165-architect | attempt=08d0f206-9df0-42c6-9470-6a7ffc65ce61 | operation=kr1165-review-r2
본 보완이 아래 지정한 r1 주장을 SUPERSEDED한다. r1 원문은 보존하며 본 문서도 구현 승인이 아니다.
기준선: PC 로컬 우선, 외부 개인데이터 전송·자동 삭제·지속 수집·원격 백업/동기화 기본 OFF. 서버 구축·수집·전송·구매·삭제·구현은 이번 범위 밖이다.

1. **재사용·설치 증거 — SUPERSEDED: §0 ‘필수 신규는 단 하나’, §3 보존/.bak 현행 보장, §4 ‘확인’의 설치 기능 해석.**
기존 소스 존재는 상속받은 검토 입력이며 설치·연결·종단 실행 증거가 아니다. 원본 저장 외 승인 큐, typed claims, STT 어댑터, 철회/삭제 경로와 새 파이프라인 연결도 구현 작업이다.
상속 검토에 따르면 installer --upgrade/--force는 manifest 관리 파일을 덮어쓴다. 일반화된 자동 .bak·사용자 데이터 보존은 제안이며 현행 보장이 아니다. 설치/업그레이드 보존 검증을 별도로 요구한다.
2. **내용과 출처 — SUPERSEDED: §1·W1·W7·§7.1의 source_id=sha256 및 같은 바이트 no-op.**
blob_hash는 바이트 식별자만 담당한다. 안정적 occurrence_id와 owner_id, 원본 출처·수집 사건, consent_id/consent_revision, revision_id를 별도로 기록하고 blob_hash에 연결한다.
동일 바이트라도 다른 출처/소유자의 occurrence와 동의 이력은 합치지 않는다. 멱등 재시도는 같은 수집 사건에만 적용하며 중복제거가 출처·권한을 제거하거나 확장하지 못한다.
동의·범위 검증을 바이트 저장보다 먼저 수행한다. 미동의 입력은 저장 없이 거부하고 quarantine은 이미 승인된 가져오기 중 실패한 자료에만 사용하며 검색에서 제외한다.
3. **권위 이력과 복구 — SUPERSEDED: §3 [D] 일괄 재생성 가능, W2/W7 단일 hash.json, W8 파생 삭제 ‘안전’, W9 재개 보장.**
provenance·동의/철회·사용자 교정·검토 결정은 내구성 있는 권위 이력이다. 전사/추출은 고유 revision_id와 부모 revision, 엔진/버전·근거 오프셋을 기록하고 이전 버전을 덮어쓰지 않는다.
재계산 결과로 검토받은 버전이나 인간 결정을 대체하지 않는다. 승인 지식은 해당 occurrence/revision/decision을 참조하고 경쟁 revision을 함께 보존한다.
다중 파일 저장은 transaction_id별 준비 기록→바이트/참조의 내구화→commit 기록→공개를 설계한다. 복구는 commit된 집합만 노출하고 미완료 집합은 비공개로 재실행/복구한다.
append-only·rename만으로 crash consistency를 주장하지 않는다. 각 단계 중단, 잘린 ledger/부분 파일, commit 후 색인 전 중단, 중복 replay fixture로 누락·이중 반영·미승인 노출 부재를 검증해야 한다.
4. **주장과 충돌 — SUPERSEDED: W4의 진실 신뢰도 해석, W6 fact>claim>inference 및 LWW 사실 판정.**
ConfidenceGuard 0.65와 claim_type은 검색/검토 휴리스틱이며 진실 확률이 아니다. ‘fact’ 표기도 사실 인증이 아니다. 경쟁 근거를 보존하고 불확실성을 표시한다.
LWW나 유형 순위는 사실 분쟁·동의·교정을 조용히 해결하지 못한다. 인간 결정의 정확한 내용·주체·범위·시각·대상 revision을 보존하며 상충하는 인간 결정도 명시적 해소 전 병존한다.
새 연결에는 승인 전 비노출, typed claims/근거 전달, 경쟁 증거 보존, 교정 적용, task 범위 격리 수락 검증이 필요하다.
5. **철회·백업 — SUPERSEDED: W8 ‘철회됨’ 표시 충분, W10 수신자 참조만으로 복원 충분.**
철회 시 권위 tombstone을 기록하고 모든 검색/직접 조회/에이전트 전달 경로에서 해당 출처의 민감한 파생 내용을 즉시 차단한다. 색인 재생성이나 물리 삭제 완료를 기다리지 않는다.
동일 blob의 다른 occurrence가 철회된 출처 내용을 우회 노출하지 않도록 파생별 출처 의존성과 접근 범위를 평가한다. 물리 삭제 경로는 별도 승인 전 사용할 수 없다.
복원은 최신 권위 tombstone과 백업 이력을 병합한 뒤에만 대상 색인을 활성화한다. 최신 철회 상태를 확인할 수 없으면 활성화를 거부하고 오래된 백업으로 동의가 부활하지 않게 한다.
내보내기는 암호화 키 식별자/복구 절차를 포함하고 별도로 보호된 복구 키 또는 암호화된 키 보관본으로 실제 복호화를 검증한다. 평문 비밀은 내보내기에 넣지 않는다. 수신자 공개 참조만으로는 불충분하다.
백업·이관은 원본 purge를 수행하지 않으며 원본 삭제 승인을 만들지 않는다.
6. **엔진·환경 — SUPERSEDED: W9 및 §9 V1의 무조건 오프라인 동작 해석, §3 범용 ~/.aigentry 고정.**
STT 인터페이스 선언은 동작하는 엔진이 아니다. 승인된 엔진과 실제 대상 기기/한국어 fixture의 정확도·RTF·메모리·오프라인·화자 처리 수락 후에만 지원을 주장한다. 현재 엔진·기기 성능은 미측정이다.
동일 core를 로컬과 향후 서버에서 사용하고 최소 storage/config 및 플랫폼 경로 어댑터만 둔다. package/runtime/user-data/backup 루트를 각각 설정하며 사용자 데이터 경로는 플랫폼 설정으로 해석한다.
근거 없이 새 daemon/DB/service나 필수 외부 의존성을 도입하지 않는다. 선택적 의존성이 필요하면 기능 한계가 명시된 무의존 fallback을 요구한다.

**이식 가능한 저장 계약 — SUPERSEDED: §3 저장 등급 및 §7.1의 네 항목만으로 충분하다는 해석.**
user-data 루트 내 역할: originals/=원본 blob, provenance/=출처·동의·철회·교정·검토/거래 이력, revisions/=버전별 전사/추출, knowledge/=승인 지식과 연결; 모두 권위 보존 대상이다.
indexes/=권위 자료에서 재구축 가능한 검색 색인/캐시. backups/=독립 설정된 백업 목적지의 검증된 스냅샷 세트이며 원본의 대체물이나 live 데이터 루트가 아니다.
논리 ID는 루트/플랫폼 변경에도 유지하고 자료 참조는 루트 상대값으로 둔다. schema-versioned export manifest에 콘텐츠 해시, 모든 참조의 닫힘, 원본·revision·교정·동의·결정·tombstone 이력과 키 복구 정보를 포함한다.
내구성 인간 결정 이력과 runtime grant를 분리한다. live PID/socket/token/lease/attempt grant는 이식하거나 실행 권위로 재사용하지 않고 대상 실행 권한을 새로 검증한다.
이관 순서: 원본 측 쓰기 정지/일관 snapshot → 다른 대상 루트로 재개 가능한 복사 → 해시·참조·schema·복호화 검증 → tombstone을 반영한 대상 색인 구축 → 명시적 cutover → 원본 보존과 rollback 가능 상태 유지.
cutover 후 새 쓰기는 단일 활성 측에서만 허용한다. rollback 전 새 변경과 철회 이력을 일관되게 회수·검증하며 실패하면 이전 snapshot을 무조건 활성화하지 않는다. 실제 서버/전송은 수행하지 않는다.
이식성/운영 주장 전 필수 fixture: 손상, 원본 누락, 동일 바이트/다른 소유자, 복사·복원 중단, 경쟁 revision, 철회 출처가 포함된 옛 백업, 변경된 루트/플랫폼, rollback 및 위 replay/부분 쓰기.

**소유권·승인 경계 — SUPERSEDED: §10 및 과거 ACK의 소유권/보존기간이 모두 구현 선행 사용자 결정이라는 주장.**
#1165는 지식 데이터 계약 소유(brain 내부 모듈 권고), #1169는 installer/bin/init 변경 소유, #1171은 설치 릴리즈 통합 소유다. 컨트롤러 기술 범위 배정이며 사용자 사업 선택 질문이 아니다.
보존기간 값·삭제 UX 미정은 자동 삭제 없는 로컬 저장 슬라이스를 막지 않는다. 파괴적 경로는 별도 승인 전 비활성이다. 저장 구현 권고와 구현 착수 권한은 별개이며 현재 구현 승인은 없다.
Task Advisor 기본 ON/제안만, Task Loop 기본 OFF/명시적 인간 활성화, 모든 에이전트 간 전송 telepty를 유지한다. Voice Code는 무시선 프롬프트/충실한 요약 브리지이며 엔진·기기 성능 완료 주장이 아니다.
