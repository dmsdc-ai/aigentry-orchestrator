# 0.2.8 task dispositions (release group `release-1293`)

This is planning evidence for `release/0.2.8.json`. A **shipping** entry means the
candidate contains the stated bytes, subject to release gates; it does not mean a
task is done, installed, accepted, or published. Publishing 0.2.8 would close no
task.

The candidate changes 37 paths relative to `v0.2.7`
(`a8b9215437008bfde490b5cec3da0fc3ea8d77c2`). Its history since that tag holds
eight squash merges on the main branch and the task 1293 branch.

Ownership was derived as follows. The ownership tool reads a trailing `(#N)` in a
commit subject as a task id. For the eight squash merges that number is the pull
request (69, 71 to 77), not a task, and the tool does not let a commit attribution
override a subject. Each path those merges touched therefore carries a human
resolution that names the task the pull request belongs to: pull request 69 is
task 1284, pull requests 71 to 76 are task 1286, pull request 77 is task 1289. One
task 1293 branch commit (`c07d3acd3`) carried the main branch's content of eleven
of those files into the branch without changing them; each of those files is
byte-identical to the main branch and is resolved to the task of its pull request.
The seven task 1293 branch commits whose subjects name no task are attributed to
task 1293 by a commit attribution. Each path has one owner.

wrapper or service still runs the telepty copy that 0.2.5 to 0.2.7 carried inside
this package, and no document can establish what a service manager will start;
the npm-side trusted publisher must be registered on the day of a release; this
workflow has no `workflow_dispatch`, so a rejected publish costs a patch version;
every Known limit of 0.2.7 still applies. These gates are separate from
completing every historical task or unsupported native capability.
