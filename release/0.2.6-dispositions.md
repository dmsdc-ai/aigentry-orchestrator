**Required companion artifact.** These paths call and print two verbs that only
`@dmsdc-ai/aigentry-telepty` 0.11.1 provides, `inject-bound-v1` and
`clear-strand-v1`. The daemon and every `telepty allow` bridge must run 0.11.1
or later, restarted: a bridge keeps the code it was started with and cannot
declare the `busy-input-v1` capability admission requires. Publishing this
orchestrator release does not publish, verify or pin that companion.

**What this candidate does not establish.** No automated test proves native busy
queueing or model receipt; `accepted` claims only that both frames were handed
to the pinned owner bridge. A real strand followed by a successful clear has not
been measured outside mocks. A collapsed one-line Claude viewport and a busy
codex footer without the warnings suffix are not bound-deliverable, so those
dispatches still end in the readiness timeout. The `set -e` defect in
`bin/dispatch-verify.sh` is unchanged. Native identity reuse, lifecycle and
installed acceptance of the boot preflight remain separate unfinished work. One
of the nine commits records that a security scan had not been run at that point;
the record for this release is `release/security/0.2.6/`, and the scan behind it
is run and adjudicated by the release controller, not by this planning record.
These gates are separate from completing every historical task or unsupported
native capability.
