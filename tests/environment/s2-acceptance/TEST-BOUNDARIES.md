# R2 fixture boundaries and execution closure

All cases are authored and **NOTRUN** in the coder phase. The independent executor must use the corrected test fixture sources with the frozen R4 product tree, compile to the normal `dist` layout, supply only the declared readonly Node dependencies, and run the selected controls and affected suites. The separate emitted `build` is syntax/type evidence, not a runnable copied-package installation.

`fixture-controls.test.ts` uses an output-owned copy of the emitted fixture module to test repeated allocation and refusal of symlink, file and insecure private temporary parents without replacing the shared suite parent. It also requires the real managed driver to prepare a writable synthetic project outside the protected package and dependency roots, then checks that the real policy still refuses a protected package-root scope. It checks Darwin and Linux fake wrapper shapes, unknown-platform refusal and the host shape against the real pinned overlay validator. The new location control is authored and unexecuted here; it does not attest native SRT.

## Managed pipeline

`_managed-driver.ts` calls the real `upgradeConfig`, `enrollProject`, `createBinding`, `resolveBinding`, `captureManagedRuntime`, `prepareWorkerSandbox` and `prepareGrant` in a child with one owned provider recorder. It keeps the sealed v2 manifest, prepared grant and payload on the real private filesystem. `runner-claims.test.ts` starts the actual `worker-sandbox-runner.js` with the sealed manifest and hash. The real `readSealedManifest`, `assertRuntimeOverlaySupported`, `controllerContext`, `claimGrant`, writer lock, durable spent write, payload read/unlink and receipt code execute. The provider recorder checks receipt of the selected fixture token without writing its bytes or a token-derived hash/length.

`_runner-preload.ts` replaces exactly these boundaries in its child: `/proc/sys/kernel/random/boot_id` or macOS `sysctl kern.bootsessionuuid` with one fixed fake boot ID; `os.userInfo`, `os.homedir`, `os.tmpdir`, `os.uptime` and `Date.now` with fixture values; `@anthropic-ai/sandbox-runtime` with `_srt-loader.ts`; the preflight child with an owned no-op Node process; and the wrapper child with the sealed command's owned provider recorder. It redirects `createRequire(...).resolve("@anthropic-ai/sandbox-runtime/package.json")` only to the declared readonly package so the real R4 overlay hash check reads the pinned SDK bytes. It pauses only before `environment/writer.lock` mkdir in the two-process race. It does not patch `claimGrant`, the manifest reader, grant/config files, `spent.json` open/write/fsync or payload unlink. Source hashes of both instrumentation files and the selected product files are in the R2 manifest.

The preload records only boundary names, argv, stdio, selected-recipient booleans and clock mode in exclusive nofollow files under the private canonical temporary fixture root. The shared allocator owns a deterministic `aigentry-s2-acceptance-<uid>` base and unique private process/fixture children. Both managed helpers check that same location, canonical path, private mode and owner before using `R2_FIXTURE_ROOT`; the child inherits the canonical TMPDIR from `childEnv`. A race starts two independent runner processes, waits for both `ready-<pid>` markers, publishes one `release` file and requires one successful provider marker. Child processes have 30 second timeouts. A failed assertion leaves its fixture directory for inspection; successful cases snapshot metadata before removing only their allocated roots.

## Terminal branches

`helper-restart.test.ts` runs the actual `wh-cli.sh open` door for cmux, warp, aterm, tmux, wezterm, iterm and headless with both launch policies. It runs the actual compiled `open-session/cli.js` caller for the six adapters its `detect_terminal` can select, plus legacy cmux and a native baseline. `workspace-host.sh` itself documents that Warp has no detection predicate; the public `wh-cli open` door reaches that branch with an explicit adapter selection. Every external terminal/daemon command resolves to an executable test-owned recorder in a pinned private PATH. Fake `uname`, `pgrep` and `osascript` answer only fixture observations; no real terminal or daemon is contacted. The recorder writes argv, environment key names, FD3 presence and canary-presence booleans, never raw canary values.

The adversarial case atomically replaces only the owned `bin/telepty` recorder after the actual `detect-terminal` subprocess returns, before the actual `wh-cli open` child. Its invariant asserts that a replacement descendant was not invoked. R4 may violate this assertion; the expected RED result is evidence for the separate product coder, not a reason to weaken the test. `open-session` has `AIGENTRY_SLEEP_GUARD=0`, so its power/session PID probes are outside this fixture. Fake command recorders never execute the terminal command they receive.

Remaining unmocked actual callers are the central dispatch entry into prepare, report pump after spend/reclaim, boot/orchestrator/gate direct routes, fallback daemon/tmux absence cases, and provider tool/hook descendants. A future product seam is needed only if independent execution shows the test-owned preload cannot reach the current R4 claim through the real overlay guard; the minimal proposed seam is an optional `RunnerPlatform` dependency passed to `main` in `src/session/worker-sandbox-runner.ts` with `wrap`, `preflight` and `spawn` methods, defaulting to the existing SRT/Node functions. No such production seam was added here.

The corrected `_runner-preload.ts` recognizes only the exact fake wrapper for the host platform and refuses any other runner `spawn` before a native shell can execute. Its first accepted call starts the owned Node preflight stub and its second starts the sealed owned provider; a third call refuses. The corrected fake wrapper includes the assignments required by `assertRuntimeOverlaySupported`, and the Darwin form starts with `env`. The independent executor still must establish these behaviors by running the controls and product suites; no native wrapper is part of this fixture.
